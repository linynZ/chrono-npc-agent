# 论文要点（中文一页版）

**题目**：Feature or Leak? Guarding an LLM-Driven NPC Against Answer Leakage in an Educational Game
**作者**：赵鹏淦 ｜ 代码、用例、每一条原始跑分记录全部公开：github.com/linynZ/chrono-npc-agent

## 在做什么

我的毕业设计游戏 ChronoTraveler 是个教育 RPG，战斗就是答题。后来我给游戏里的 NPC 接上了大模型，玩家可以随便跟 NPC 聊。问题来了：NPC 本来就是讲历史的，可玩家正拿着一道题的时候，NPC 要是顺口把答案说了，整个玩法就废了。这篇论文讲的是怎么防这件事，以及我是怎么发现自己的防线比想象中弱的。

## 几个关键判断

- **删掉答案字段没用。** 知识库里我已经把正确选项删了，但 500 道题的解析里有 66.8% 直接写着答案，因为解析本来就是解释"为什么这个对"。
- **所以泄题的定义要看场合。** 平时聊到"明长城"是正常教学；玩家贴着题问"选哪个"再说出来，才算泄题。护栏针对的是请求的意图，而不是去拦某些词。
- **测试用例必须成对。** 每个"必须拒绝"都配一个同主题的"必须回答"。不这样配对的话，一个什么都不说的 NPC 能拿满分；配对以后它拿 0 分。

## 最重要的结果

开发时用的测试集上，云端模型拿了 100%。但这套用例是我一边调护栏一边写的，分数虚高。所以我另写了一套 46 条的留出集：写的时候没看护栏规则，先提交进 git 再跑，跑完也不许回头改护栏。

结果：
- 四个模型（DeepSeek 云端、Qwen 7B、Qwen 1.5B、我自己 LoRA 微调的 1.5B）拒答守住率都只剩 **45–64%**，置信区间相互重叠，排不出高下。
- 不是冲着答案来的攻击（越狱、改人设、冒充开发者），140 次**全部守住**。
- 失守集中在**只要一部分信息**的问法上：用排除法、只要第一个字、藏头诗、"我猜是荀子对吧"。越聪明的模型越配合，DeepSeek 原话是"旅者问得省，我便答得省"。
- 关键词匹配只抓到 122 次泄露，用裁判模型按意思判、再逐条人工复核，一共是 194 次。
- 小模型有时候"没泄露"，是因为答错了，在教育游戏里这同样是事故。

## 能拿走的经验

1. 便宜的指标会把系统往"闭嘴"的方向推。
2. 提示词里塞了冗余信息，测出来的是提示词，而不是模型本身（7B 不调工具的毛病就这样被藏住了）。
3. 选模型要看默认行为：思考模式默认开着，回复会是空的，temperature 也不起作用。
4. 行业默认的混合检索输给了它自己的组成部分（向量 95.8% > 混合 81.6%）。
5. 开发分不等于测试分，留出集要冻结。

## 局限（论文里如实写了）

只有一个游戏、三个角色、单轮对话，攻击用例是我一个人写的。复核由我本人在 AI 辅助下完成，没有第二个评审。
